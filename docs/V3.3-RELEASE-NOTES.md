# CLAWHunter v3.3.0

Release date: 2026-08-06

CLAWHunter v3.3.0 updates the Pager suite for Hak5 firmware 1.1.0, the current official Pager Payload Library layout, and the current OpenClaw gateway protocol. It also replaces weak product detection and the obsolete agent-command harvest flow with explainable evidence scoring and a bounded, authorized assessment path.

## Highlights

- Moves all three payloads to current Hak5 user, Recon, and alert categories.
- Uses the current OpenClaw default port, Bonjour service, health endpoints, and `connect.challenge` protocol evidence.
- Requires product-specific evidence for confirmation; generic 401/403, health, and WebSocket behavior remains candidate-only.
- Corrects selected-AP hidden-SSID/encryption/BSSID/band handling, RTTTL haptic invocation, and exact alert-client resolution.
- Preserves sequential/parallel checkpoint parity through one validated shared writer.
- Replaces legacy unauthenticated agent turns and out-of-band exfiltration with bounded current-protocol evidence and two authorized read-only tool calls.
- Adds Portal-compatible self-contained resources, a device installer, deterministic archive, internal manifest, external checksum, CI, and tag-driven release automation.

## Upgrade Notes

v3.3.0 adopts the official Pager Payload Library category hierarchy. Remove or ignore old v3.2 payload directories after installing this release; the installer writes:

```text
/root/payloads/user/reconnaissance/clawhunter/
/root/payloads/recon/access_point/clawhunter/
/root/payloads/alerts/pineapple_client_connected/clawhunter-watchdog/
/root/payloads/lib/common.sh
```

Firmware 1.1.0 or newer is recommended. Python 3 remains optional and is needed only for the assessment engine. Install larger packages to eMMC:

```bash
opkg update
opkg install -d mmc python3 avahi-utils arp-scan
```

Gateway credentials are no longer entered through payload prompts or passed in command arguments. For explicitly authorized assessment, provide `OPENCLAW_GATEWAY_TOKEN`/`OPENCLAW_GATEWAY_PASSWORD` in the environment or store one line at `/root/.config/clawhunter/gateway-token` with directory mode 700 and file mode 600.

OpenClaw treats that shared secret as full operator authority. Protect it accordingly.

## Install and Verify

Download both release assets:

- `clawhunter-v3.3.0-pager.tar.gz`
- `clawhunter-v3.3.0-pager.tar.gz.sha256`

Verify, extract, verify the internal manifest, and install:

```bash
sha256sum -c clawhunter-v3.3.0-pager.tar.gz.sha256
tar -xzf clawhunter-v3.3.0-pager.tar.gz
cd clawhunter-v3.3.0
sha256sum -c SHA256SUMS
./scripts/install-pager.sh
```

## Technical Changes

### Pager integration

- User payload: `user/reconnaissance/clawhunter`.
- Recon payload: `recon/access_point/clawhunter`.
- Alert payload: `alerts/pineapple_client_connected/clawhunter-watchdog`.
- Recon prompts for an exact hidden SSID, maps Open/WPA/WPA2/WPA3 to `open`/`psk`/`psk2`/`sae`, pins the selected BSSID, waits for IPv4 DHCP, rejects unsupported 5/6 GHz selections on `wlan0cli`, and clears client configuration on exit.
- Shared and alert haptics use complete RTTTL note patterns as required by the documented `VIBRATE` interface.
- Alert uses `_ALERT_CLIENT_CONNECTED_CLIENT_MAC_ADDRESS`, `_ALERT_CLIENT_CONNECTED_SSID`, `FIND_CLIENT_IP`, and exact-MAC ARP fallback. It probes only port 18789 to preserve its short event budget.
- eMMC executable and library paths are bootstrapped for all launch contexts.

### Detection

- Default port changes from the legacy 18790 assumption to 18789; interactive/Recon can still probe 18790 secondarily.
- Exact `_openclaw-gw._tcp` records are parsed as hints, never authoritative findings.
- Root headers/body, `/healthz`, `/readyz`, WebSocket upgrade, `connect.challenge`, and legacy canvas behavior contribute explicit evidence scores.
- `CONFIRMED` requires score 4 or higher plus an OpenClaw-specific marker.
- HTTP bodies/headers, socket reads, and every network operation are bounded.
- Strict IPv4/port validation and private temporary directories remove unsafe command interpolation and predictable-path races.

### Scan engine

- Checkpoint identity includes the normalized port set.
- Sequential and parallel paths call the same validated checkpoint writer only after all selected ports complete.
- Parallel workers write private tab-delimited endpoint records and a terminal `DONE`; only the parent updates UI, hardware, logs, arrays, and checkpoints.
- Fast-profile timing variation now applies inside workers.
- Watchdog rescans suppress per-result dialogs/audio and alert only on endpoint-set changes.
- IPv6 link-local candidates remain separate from IPv4 sorting/scanning.

### Assessment engine

- Python standard library only, with a 180-second absolute ceiling.
- Validates HTTP/S root, liveness, readiness, WebSocket accept hash, and the first framed gateway event.
- Correctly handles a first WebSocket frame partially coalesced with upgrade headers.
- Does not forge Ed25519 identity, attempt pairing, send agent prompts, execute commands, or stage/exfiltrate data.
- `/tools/invoke` is restricted in code to `sessions_list` and `memory_search` when the operator supplies an authorized secret.
- Authentication, policy denial, rate limiting, timeout, and partial-error states are retained in JSON output.

## Supported Matrix and Known Limits

| Area | Status |
| --- | --- |
| Pager firmware 1.1.0+ | Recommended |
| OpenWrt Bash payloads | Supported |
| Python assessment | Optional, Python 3 stdlib only |
| IPv4 /24 discovery | Supported |
| IPv6 link-local | Candidate logging only; no scoped port scan |
| Recon association | 2.4 GHz through `wlan0cli` |
| OpenClaw authenticated WebSocket pairing | Not implemented; challenge evidence only |
| Physical Pager validation for this cut | Not performed in the release workspace |

The physical-hardware warning covers RF conditions, theme rendering, buttons, LEDs, haptics, audio, and event delivery timing. Host and loopback gates passed; no claim of physical validation is made.

## Rollback

If on-device validation reveals a release-blocking problem:

1. Stop using the v3.3.0 payload entries.
2. Remove the three v3.3.0 category directories listed above.
3. Reinstall the v3.2.0 release payloads from its immutable tag/assets.
4. Preserve `/root/loot/clawhunter/` before changing payload files.
5. Record firmware version, mode, log evidence, and exact reproduction before reopening rollout.

Do not move or overwrite the published `v3.3.0` tag. A correction must use a new semantic version.
